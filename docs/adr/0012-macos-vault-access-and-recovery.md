# macOS vault access and recovery / Доступ к сейфу и восстановление на macOS

The macOS app owns the unlocked vault. Each device has its own master password, recovery phrase, optional Touch ID registration and local integration permissions. A portable backup carries vault content. The destination keeps its own unlock credentials.

Приложение macOS владеет открытой сессией сейфа. У каждого устройства свои мастер-пароль, фраза восстановления, регистрация Touch ID и разрешения локальных интеграций. Переносимая копия содержит данные сейфа. На принимающем устройстве остаются его собственные средства входа.

| Surface / Граница | Protection and limits / Защита и ограничения |
| --- | --- |
| Copied vault / Копия файла сейфа | The master password derives a wrapping key with Argon2id. A separate recovery key derives from the entropy of the 24 words. Both can open the encrypted payload. Optional hints are visible before unlock. / Argon2id выводит из мастер-пароля ключ для расшифровки ключа сейфа. Из энтропии 24 слов выводится отдельный ключ восстановления. Оба способа открывают зашифрованные данные. Подсказки видны до входа. |
| Unlocked session / Открытая сессия | Rust owns the data key. Lock invalidates the session generation and drops the key and pending confirmations. Visible fields, user-initiated exports and the system clipboard can contain plaintext. Dart strings, third-party clipboard managers, OS diagnostics and processes with debugger privileges are outside the memory-erasure guarantee. / Rust владеет ключом данных. Блокировка меняет поколение сессии, освобождает ключ и отменяет ожидающие подтверждения. Открытые поля, экспорт владельца и системный буфер могут содержать открытый текст. Гарантия очистки памяти не распространяется на Dart-строки, сторонние менеджеры буфера, системную диагностику и процессы с правом отладки. |
| Touch ID | An explicit enrollment creates a device-only, unsynchronized Data Protection Keychain item restricted to the current biometric set. Its account identifies the vault's key wrappers. Unlock verifies the payload and checks the file and session after the system prompt. Password entry remains available when Touch ID fails or is cancelled. / Регистрация создаёт локальную несинхронизируемую запись Data Protection Keychain, привязанную к текущему набору отпечатков и ключам конкретного сейфа. После системного запроса приложение проверяет шифротекст, файл и сессию. При отказе или отмене остаётся вход по паролю. |
| Per-operation TOTP / Подтверждение действий | Enrollment requires a fresh six-digit code from a separate authenticator. The encrypted policy records the last accepted counter and retry delays. A permit is bound to the operation, subject, policy, content revision and session. It expires after 30 seconds or its first use. A secret-value search cannot reveal protected fields through match results. This policy applies to the running application. Offline decryption still depends on the master password or recovery phrase. / Для подключения нужен свежий шестизначный код отдельного аутентификатора. В зашифрованной политике хранятся последний принятый счётчик и задержка повторной попытки. Разрешение привязано к действию, объекту, политике, версии содержимого и сессии. Оно действует 30 секунд или до первого использования. Поиск скрытых значений не выдаёт совпадения. Политика действует внутри приложения. Для офлайн-расшифровки достаточно мастер-пароля или фразы восстановления. |
| Recovery and backup / Восстановление и копия | Full recovery replaces the local wrappers and optional TOTP factor. A portable backup uses an X25519 HPKE recipient derived from the phrase held at export. Rotating a phrase affects future exports. Someone with an old archive and its original phrase can still open that archive. Restore requires an explicit replacement or reviewed merge. / Полное восстановление заменяет локальные обёртки ключа и сбрасывает внешний TOTP. Для переносимой копии используется получатель X25519 HPKE, производный от фразы на момент экспорта. Смена фразы действует для будущих копий. Для прежнего архива и впредь подходит его исходная фраза. Восстановление требует явной замены либо объединения после просмотра конфликтов. |
| Local CLI and SSH / Локальные CLI и SSH | The app verifies the local socket peer and presents the proposed scope. A signed helper identifies a binary. Its signature cannot identify the shell, script or person that invoked it. A profile restricts SSH to a user, host key and permitted key fields. The SSH wire operation uses the protected private key internally. Public-key export is explicit. / Приложение проверяет процесс на локальном сокете и показывает запрошенные права. Подпись утилиты удостоверяет бинарник. Она не удостоверяет оболочку, скрипт или человека, запустившего команду. SSH-профиль ограничивает пользователя, ключ хоста и доступные поля ключевой карточки. Подпись выполняется внутри сейфа. Экспорт открытого ключа требует отдельного действия. |
| Development and production / Разработка и production | The production bundle ID is `foundation.want.pass`, the development ID is `foundation.want.pass.dev`. Their vault directories and Keychain services differ. A fresh production installation creates its own vault. / Bundle ID production — `foundation.want.pass`, разработки — `foundation.want.pass.dev`. У сборок разные каталоги сейфа и сервисы Keychain. Новая production-установка создаёт собственный сейф. |

The supported outcome for cancellation, stale revision, missing device trust or a denied operation is a closed operation. Only the owner initiates disclosure, file selection or clipboard use. Real-device biometric acceptance and Gatekeeper acceptance require the signed release and separate evidence.

При отмене, устаревшей ревизии, отсутствии доверия к устройству или отказе разрешения действие прекращается. Раскрытие, выбор файла и работу с буфером инициирует владелец. Приёмка Touch ID на устройстве и проверка Gatekeeper требуют подписанного выпуска и отдельных результатов.
