# Portable vault backup / Переносимая копия сейфа

## Export and restore / Экспорт и восстановление

In General settings → Backups, choose Export backup and select a folder. Want Pass creates a new encrypted `.wpassbackup` file there and displays its name. Each name contains a timestamp and a unique suffix. Existing files are preserved. Store the 24 recovery words that were active when you exported it. Each backup remains tied to that phrase, including after a password recovery that issues new words.

В общих настройках откройте «Резервные копии» → «Экспорт копии» и выберите папку. Want Pass создаст в ней зашифрованный файл `.wpassbackup` и покажет его имя. Имя включает дату, время и уникальный суффикс. Существующие файлы сохраняются. Сохраните 24 слова, действовавшие при экспорте. Они понадобятся для этой копии и после восстановления доступа с выдачей новой фразы.

On a new installation, select Restore an encrypted backup after setup. Create a local master password, save the new device's recovery words and finish setup. Then select the backup and enter its original phrase. On an existing vault, choose Restore backup in General settings. The question-mark menu on the locked password field can open the same flow after sign-in.

На новой установке отметьте «Восстановить копию после настройки». Создайте локальный мастер-пароль, сохраните новую фразу и завершите настройку. Затем выберите файл копии и введите фразу от него. В существующем сейфе восстановление доступно в общих настройках. Из меню «?» в поле пароля этот же экран откроется после входа.

Enter words in 24 numbered fields, or paste text separated by spaces, commas or lines. The input also accepts numbered lines, a JSON array and the numbered JSON object exported during setup. The native parser checks the English BIP39 words and checksum. The clipboard button reads only on request. Pressing Space or Tab moves between fields. Backspace in an empty field returns to the previous word.

Введите слова по одному в 24 пронумерованных поля или вставьте текст с пробелами, запятыми либо переносами строк. Также принимаются пронумерованные строки, JSON-массив и JSON-объект с номерами из мастера настройки. Rust проверяет английские слова BIP39 и контрольную сумму. Кнопка вставки читает буфер по нажатию. Пробел или Tab переключает поле, Backspace в пустом поле возвращает к предыдущему слову.

Choose **Merge** to keep local records. For each conflicting entry, keep the current version, use the incoming version, or keep both. Keeping both gives the second version its own ID. Using the incoming version of a card moves the previous local version into the 365-day history. Related incoming cards and history follow that ID and can produce additional conflicts in the preview. Importing the same data again recognizes the earlier copies. **Replace** presents the number of additions, changes and removals and requires a separate confirmation. The target keeps its own password, recovery phrase and external authenticator policy. Device permissions and system SSH configuration stay local. Full replacement removes existing SSH profiles from the vault. A merge keeps local profiles for unchanged key material and bindings. The removal count includes the SSH profiles that the selected strategy will discard. Both strategies revoke active operation and tool grants.

При **объединении** для каждого конфликта можно оставить текущую версию, взять входящую или сохранить обе. При сохранении обеих версий копия получает свой ID. При выборе входящей версии карточки предыдущая локальная версия попадает в историю на 365 дней. Входящие карточки и история сохраняют связь с ней, поэтому предпросмотр может запросить дополнительные решения. При повторном импорте уже созданные копии распознаются. При **полной замене** пользователь видит число добавлений, изменений и удалений и подтверждает замену отдельно. У целевого сейфа сохраняются собственные пароль, фраза и политика внешнего аутентификатора. Разрешения устройства и системные SSH-конфиги остаются локальными. Полная замена удаляет SSH-профили из данных сейфа. Объединение сохраняет локальные профили для прежнего ключевого материала и привязок. В число удалений при предпросмотре входят SSH-профили, которые будут удалены при выбранном способе восстановления. Оба способа отзывают действующие разрешения операций и инструментов.

## File format / Формат файла

The first eight bytes are the ASCII string `WPBACK` followed by `00 01` in hex. The next 16 bytes identify the source vault, followed by the 32-byte HPKE encapsulated key and ciphertext with its 16-byte authentication tag. The complete 56-byte header is authenticated associated data. The encrypted JSON contains schema 3, its revision, groups, cards, services, templates and retained history. The native reader bounds the size before decrypting and validates the portable document before a preview or write.

Первые восемь байт содержат ASCII `WPBACK`, затем `00 01` в hex. Далее идут 16 байт ID исходного сейфа, 32 байта инкапсулированного HPKE-ключа и шифротекст с 16-байтовым тегом. Все 56 байт заголовка аутентифицируются как associated data. В зашифрованный JSON входят схема 3, её ревизия, группы, карточки, сервисы, шаблоны и сохранённая история. Rust ограничивает размер до расшифровки и проверяет документ до предпросмотра и записи.

The cryptographic suite uses RFC 9180 base-mode DHKEM(X25519, HKDF-SHA256), HKDF-SHA256 and ChaCha20-Poly1305. HKDF-SHA256 takes the 32-byte BIP39 entropy, vault ID as salt and `WantPass/backup-recipient/v1` as info. Its 32-byte output feeds DHKEM DeriveKeyPair. The encrypted local payload version 2 stores only the public recipient alongside the document. Export uses a fresh ephemeral key for each file. An installation with a legacy payload version 1 can create a recipient through the full recovery flow. Recovery changes the recipient of future exports. The phrase alone cannot recover data after deletion of both the vault and its backups. [RFC 9180](https://www.rfc-editor.org/rfc/rfc9180.html)

Копия использует базовый режим RFC 9180 с DHKEM(X25519, HKDF-SHA256), HKDF-SHA256 и ChaCha20-Poly1305. Исходные данные HKDF — 32 байта энтропии BIP39, соль — ID сейфа, параметр info — `WantPass/backup-recipient/v1`. Полученные 32 байта поступают в DHKEM DeriveKeyPair. Локальный зашифрованный payload версии 2 хранит рядом с документом только открытый ключ получателя. У каждого экспорта свой эфемерный ключ. Для ранее созданного payload версии 1 открытый ключ создаётся через полный сценарий восстановления доступа. После него будущие экспорты привязаны к новой фразе. Для возврата данных после удаления сейфа нужны файл копии и подходящая фраза. [RFC 9180](https://www.rfc-editor.org/rfc/rfc9180.html)
